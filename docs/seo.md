# SEO 配置与提交

代码维护规范：

- `SITE_URL=https://blog.ittx.cn` 是 canonical、文章分享地址和结构化数据的站点地址；迁移域名时一起更新 `public/robots.txt` 的 Sitemap 地址。
- sitemap 只使用显式公开来源，不自动收集 Nuxt 后台、登录、注册或简历打印路由。只包含已发布且到达发布时间的文章，以及有公开文章的分类、标签。缓存最长刷新周期还取决于反向代理配置。
- 后台、认证、API 和打印入口通过 `X-Robots-Tag` 禁止索引。不要在 robots.txt 阻止这些 HTML 页面后，又期待爬虫读取它们的 noindex。访问权限仍由服务端认证管理。
- 文章规范地址为 `/<slug>.html`，存在的无后缀文章地址 301 到规范地址。分页有真实链接，每页使用自己的 canonical；搜索与筛选结果 noindex，普通分类/标签页可索引。
- 首页标题、站点摘要优先采用后台设置；默认“个人博客”副标题和空摘要使用技术博客的 SEO 文案。自定义副标题会同步影响网站可见的副标题。
- 文章分享图使用绝对地址，BlogPosting 使用页面真实的作者名称与时间。没有单独作者资料时使用侧栏作者名称或站点名称，不虚构作者与日期。
- 生产构建生成静态资源的 gzip/Brotli 文件；反向代理直接提供静态文件时，也需配置使用预压缩文件或启用压缩。

站长操作：

1. 登录 Google Search Console，添加站点，按平台给出的 DNS TXT 或其他方式验证域名。DNS 记录由域名所有者添加，验证后保留。
2. 在 Sitemap 栏提交 `https://blog.ittx.cn/sitemap.xml`，用 URL 检查工具抽查首页、一个文章页和分类页。新文章可请求索引；是否收录与排名由搜索引擎决定。
3. Bing Webmaster Tools 可在 Google 验证完成后导入站点；如重点面向百度搜索，再在百度搜索资源平台完成验证和链接提交。
4. 在后台「站点设置 → SEO 设置」确认没有打开屏蔽搜索引擎的选项，填写准确的站点摘要。发布文章时补充实际摘要、封面、来源、测试过程和内部相关文章链接。
5. 用 Search Console 的索引、效果和 Core Web Vitals 报告观察变化；后台页面不会参与索引属于预期，不要为此取消 noindex。

本次技术改动没有数据库迁移，也不会修改已发布文章。生效前需要正常发布代码；仅刷新浏览器不会更新服务器版本。
