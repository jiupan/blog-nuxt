# 图库用途与兼容规则

图库分为图片素材、随机封面池、表情素材。分类是用途，不代表上传方式。

- 新上传的文章专用封面（编辑器与 Agent 的 `purpose=cover`）默认属于图片素材，不自动参与随机选取。现有上传接口及文件 URL 保持兼容。
- 后台在随机封面池内上传时，会显式加入随机池。普通图片也可通过批量操作加入；移出只修改用途，不改变文件地址。
- 历史 `covers/` 图片在没有用途元数据时继续属于随机池，避免升级时静默清空既有随机封面来源。历史文章专用封面无法自动识别，管理员可手动移出。
- 文章保存时从启用的随机封面中选取一张并保存地址。停用只影响后续选取，不替换已有文章封面。
- 自动选封面时优先避开近期文章使用过的图片；都使用过时优先选最久未用的。池内只有一张时仍允许复用，并发保存不保证完全不重复。
- 表情素材当前用于首页装饰与写作插图，不等同于评论面板中的 Emoji/颜文字。移动分组通过元数据实现；删除非空分组会将图片归到未分组，文件与 URL 保留。

## 引用与删除

详情显示文章封面、正文及站点设置中的直接地址引用。批量删除先检查引用并保留已引用项，服务端删除时再次检查。动态选取的首页装饰和站外引用不在静态引用列表中。

尚有直接引用的图片禁止删除，请先替换引用；随机封面可先停用。该检查与文章写入不是同一事务，不能作为跨并发编辑的严格外键约束。

## 存储与备份

用途、启用状态、分组覆盖及原文件展示名称保存在上传根目录的 `.gallery.json`，分组列表沿用 `memes/.groups.json`。**备份和恢复上传卷时必须包含隐藏的元数据文件**，仅恢复图片文件会丢失用途和分组调整。

元数据通过临时文件和原子替换保存，进程内写入串行化，适用于当前单实例部署；扩展为多个独立写入进程前，应将元数据改为共享事务存储。损坏的元数据会显式报错，不会当作空配置覆盖。

## 上传与后续扩展

上传队列逐文件记录结果，单张失败不阻断后续文件；失败重试保留最初目标图库和分组。上传新图片时保留原文件名用于展示，实际存储文件名及 URL 不变。

当前仍是文件系统全量扫描与前端分页，每页按实际网格列数显示三行，窗口宽度变化时重置到第一页。最后一页不足三行时显示剩余图片。服务端分页、索引及更完整的资源引用关系不属于本批次。
